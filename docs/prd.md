# PRD — tom-mall 商城产品需求文档

> 版本：v1.1
> 更新时间：2026-04-29
> 技术栈：EggJS + MySQL | Vue3 + Element Plus | 微信小程序

---

## 一、项目概述

tom-mall 是一个面向大众消费者的自营电商商城，由三端组成：

| 端 | 技术栈 | 使用对象 |
|---|---|---|
| 服务端（API） | EggJS + MySQL + JWT | 所有端共用 |
| 后台管理系统 | Vue3 + Vite + Pinia + Vue Router + Element Plus + ECharts + dayjs + axios | 管理员 |
| 用户端 | 微信小程序原生开发 | 普通买家 |

---

## 二、用户角色

### 2.1 买家（小程序用户）
通过微信小程序授权登录，完成商品浏览、加购、下单、支付、查看订单等操作。

### 2.2 管理员（后台用户）
通过后台管理系统账号密码登录，进行商品管理、订单处理、会员查看、权限配置等操作。

| 角色 | code | 职责 |
|---|---|---|
| 超级管理员 | super_admin | 拥有所有权限，可管理其他管理员 |
| 运营人员 | operator | 商品、订单管理 |
| 客服人员 | customer_service | 订单查看与处理 |

| 排序 | 按销量 / 价格升降序 / 上架时间排序 |
| 分页 | 小程序使用触底加载更多，每次 20 条；后台使用分页器 |
| 展示字段 | 主图、商品名、最低价、销量 |

#### 3.2.4 商品详情
| 功能 | 说明 |
|---|---|
| 基本信息 | 名称、副标题、品牌、主图轮播（product_images） |
| 图文详情 | 富文本 HTML，小程序用 rich-text 渲染 |

| 价格展示 | 售价（price）+ 划线原价（original_price） |

#### 3.2.5 SKU 规格选择联动逻辑

服务端返回 `attributes`（规格定义）和 `skus`（SKU 列表），前端实现联动：

```
1. 渲染所有规格维度和选项（来自 product_attributes.attr_values）
2. 用户点击某规格值 → 记录到"已选规格"对象
3. 遍历 skus 列表，找出所有与已选规格匹配的 sku 子集
4. 对每个尚未选择的规格维度，判断其每个选项值是否存在于子集中
   - 存在且 stock > 0、status = 1 → 可选
   - 不存在或 stock = 0 → 置灰（disabled）
5. 所有维度都选完后，在 skus 中找到 specs 完全匹配的记录
   → 展示该 sku 的价格、划线价、库存状态（有货/无货）
```

#### 3.2.6 后台商品管理
| 功能 | 说明 |
|---|---|
| 商品列表 | 分页，按分类/状态/关键词筛选，展示缩略图、名称、价格区间、总库存、状态 |
| 新增商品 | 基本信息 + 轮播图上传 + 图文详情（富文本编辑器）+ 规格属性 + SKU 表格 |
| 编辑商品 | 全部字段可修改，SKU 支持增删改 |

### 3.4 订单模块

#### 3.4.1 创建订单
| 功能 | 说明 |
|---|---|
| 确认页数据 | 收货地址 + 商品列表 + 费用明细（调预览接口） |
| 地址选择 | 默认填入用户默认地址，可切换或跳转新增地址页 |
| 费用计算 | 服务端计算：total_amount - discount_amount + freight_amount = pay_amount |
| 运费规则 | 订单金额 ≥ system_configs[freight.free_amount] 则免运费，否则收 default_fee |
| 备注 | 可选，最多 100 字 |
| 库存校验 | 提交时服务端校验，不足返回 code:1001 |
| 下单事务 | 校验库存 → 扣减库存（行锁）→ 创建 order + order_items → 清除已购 cart 记录，全部在一个事务内 |

#### 3.4.2 订单状态流转

```
待付款(0) ──支付成功──▶ 待发货(1) ──后台发货──▶ 待收货(2) ──确认收货──▶ 已完成(3)
    │                                                    │
    │ 用户取消/超时未付（30分钟）                      申请售后
    ▼                                                    ▼
 已取消(4)                                           售后中(5)
```

| 状态 | 值 | 用户可操作 | 管理员可操作 |
|---|---|---|---|
| 待付款 | 0 | 去支付、取消订单 | — |
| 待发货 | 1 | — | 填写快递发货 |
| 待收货 | 2 | 确认收货 | 查看物流信息 |
| 已完成 | 3 | 申请售后（MVP 仅预留入口） | — |
| 已取消 | 4 | — | — |
| 售后中 | 5 | — | — |

#### 3.4.3 超时自动取消实现方案

使用 EggJS 内置定时任务（`app/schedule/`）实现，**不依赖 Redis**（MVP 阶段）：

```js
// app/schedule/cancel_timeout_orders.js
module.exports = {
  schedule: {
    interval: '5m',   // 每 5 分钟执行一次
    type: 'worker',   // 单 worker 执行，防止多进程重复
  },
  async task(ctx) {
    // 查询 status=0 且 created_at < NOW()-30分钟 的订单
    // 批量更新 status=4，归还库存（循环更新 product_skus.stock）
  }
}
```

> 后期可替换为 Redis 延迟队列（如 Bull），对外接口不变。

### 3.7 系统管理（后台）

#### 3.7.1 管理员管理
新增、编辑、禁用/启用、软删除管理员，分配角色，超级管理员可重置他人密码。

#### 3.7.2 角色管理
新增、编辑、删除角色，为角色分配菜单树（勾选式）。删除角色前检查是否有管理员关联。

#### 3.7.3 菜单管理
树形结构，支持三种类型：目录（type=1）/ 菜单（type=2）/ 按钮权限（type=3）。
按钮类型需填写 permission 字段（如 `product:create`），用于接口鉴权。
有子菜单时不允许删除父菜单。

## 四、非功能性需求

| 项目 | 要求 |
|---|---|
| JWT 有效期 | 小程序 Token：7 天；后台 Token：8 小时 |
| Token 失效处理 | 小程序端 Token 过期后调用 wx.login 重新静默登录获取新 Token，无需用户感知 |
| 密码加密 | bcrypt，saltRounds=10 |
| 软删除 | 商品、用户、管理员有 deleted_at 字段，查询统一加 WHERE deleted_at IS NULL |
| 防超卖 | 下单事务内使用 SELECT ... FOR UPDATE 锁定 SKU 行再扣减 |
| 图片上传（后台） | multipart/form-data 上传到服务端，服务端转存 OSS，返回访问 URL |
| 图片上传（小程序） | wx.chooseMedia 选图 → wx.uploadFile 上传到 /api/v1/mp/upload |
| 图片 URL 规范 | 数据库统一存储完整 URL（含域名），接口直接返回，前端不做拼接 |
| 金额精度 | 所有金额字段使用 DECIMAL(10,2)，服务端用字符串或整数（分）传输，避免浮点精度问题 |
| 接口响应时间 | P99 < 500ms |
| 并发 | 支持 1000 并发下单 |
| 安全 | 所有接口必须鉴权，防止越权访问 |
| 日志 | 关键操作必须记录（登录、订单、支付） |
| 可扩展性 | 后续支持优惠券、评价、秒杀 |
